GOAL: Enable a system operator to fully assess a system end-to-end in Google Chrome until the system is formally assessed with all controls evaluated and any gaps/CAPs recorded.

Required user flows (must all work in Chrome):

1. Create System
   - Operator can manually create a new system that is an exact duplicate of the existing AI production system.
   - The architecture diagram for the new system must be identical to the current AI production environment.
   - Must be able to add/edit all assets, data relationships, and important system properties.

2. Scope Controls
   - Using the Control Scope Wizard, operator can manually mark every control as In Scope or Out of Scope for that system.

3. Evaluate Controls
   - For every In-Scope control the operator can:
     - Score each of the 5 PRISMA levels (Policy, Procedure, Implemented, Measured, Managed) using 0 / 25 / 50 / 75 / 100, for ALL 100+ controls.
     - Attach evidence to any PRISMA level (for now, evidence can simply be free-text notes — no real file upload or object store is required) for ALL 100+ controls.
     - Add an overall comment for the control for ALL 100+ controls.
   - Support recording partial coverage as a Finding/Gap (example: “MFA only covers 50% of the environment”) and link it to a Corrective Action Plan (CAP).  Create a finding for approximately 10% of the controls.
   - The user experience sould be simple and modern for each control you evaluate.  It should not be difficult to navigate.  

4. Completion
   - Once all in-scope controls are evaluated (with any gaps/CAPs recorded), the system is considered formally assessed.

STRICT CONSTRAINTS – DO NOT DO THE FOLLOWING:
- Do not add authentication / login / user management
- Do not introduce a real database (Postgres, SQLite, etc.)
- Do not add any middleware API layer or backend server
- Do not turn this into a production-ready multi-user system
- Stay within the current prototype architecture (client-side / existing graph + engine + React pages)

HITRUST SCORING RULE:
- Scoring of controls (including the 5 PRISMA levels, evidence attachment, gaps, and CAPs) must stay true to the official HITRUST method and scoring rules.
- If there is any conflict between the current engine’s logic and official HITRUST scoring rules, prioritize and implement the official HITRUST method.

LOOP & COMPLETION RULES:
- Keep iterating until the full operator workflow works end-to-end in Chrome with no missing features or blockers.
- Do not stop early. Do not declare the task done until a real user can complete all four stages (Create System → Scope Controls → Evaluate Controls with text evidence + gaps/CAPs → Formal assessment complete).
- After every major change, re-evaluate whether the full flow is now possible. If it is not, continue working.
- Only stop when the entire goal is achieved.
